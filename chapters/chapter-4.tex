\subsubsection{Statistik Dashboard Dosen}

Dashboard Dosen menampilkan ringkasan statistik komprehensif yang memberikan gambaran umum tentang aktivitas dan kinerja sistem. Statistik ini ditampilkan dalam bentuk kartu metrik yang mudah dipahami di bagian atas dashboard, mencakup tiga kategori utama:

\begin{enumerate}
	\item \textbf{Total Tugas Telah Dibuat}: Menampilkan jumlah total tugas (assignment) yang telah dibuat dosen di seluruh kelas. Metrik ini membantu dosen memantau produktivitas dalam pembuatan tugas pembelajaran.
	\item \textbf{Total Kelompok Berhasil Dibentuk}: Menunjukkan jumlah total kelompok mahasiswa yang telah berhasil dibentuk melalui algoritma pembentukan kelompok berbasis multi-faktor (MBTI, Skill, Gender, Preferensi Topik). Metrik ini mengindikasikan seberapa banyak pengelompokan telah diselesaikan.
	\item \textbf{Kualitas Kelompok}: Merepresentasikan skor kualitas dari kelompok-kelompok yang dibentuk, ditampilkan dalam format statistik deskriptif dengan tiga nilai: nilai minimum (Min), nilai maksimum (Max), dan rata-rata (Mean) dari semua skor kualitas kelompok dalam persentase. Skor kualitas ini mencerminkan tingkat keseimbangan dan heterogenitas dalam kelompok berdasarkan berbagai dimensi kepribadian, keahlian, dan preferensi mahasiswa.
\end{enumerate}

Gambar \ref{fig:4.dashboard-statistics} menunjukkan tampilan statistik dashboard dosen dengan ketiga metrik utama yang memberikan informasi ringkas tentang aktivitas dan kinerja pembentukan kelompok dalam sistem.

Terdapat 16 tes integrasi Edu2Com API tambahan yang di-\textit{skip} secara default dalam eksekusi tes reguler. Tes integrasi ini dibagi menjadi dua kategori:

\begin{enumerate}
	\item \textbf{Tes Validasi Kontrak (8 tes)}: Memvalidasi bahwa \textit{payload} yang dikirim ke Edu2Com API sesuai dengan spesifikasi kontrak. Tes ini memverifikasi berbagai skenario seperti pembentukan tim seimbang, distribusi jumlah mahasiswa ganjil, konfigurasi bobot algoritma, preferensi mahasiswa, dan \textit{skill similarity}. Tes validasi kontrak selalu dijalankan bersama tes unit utama.

	\item \textbf{Tes Integrasi Langsung (8 tes)}: Melakukan \textit{HTTP request} nyata ke layanan Edu2Com API eksternal untuk memverifikasi bahwa sistem dapat berinteraksi dengan layanan eksternal dengan benar. Edu2Com adalah layanan cerdas yang membantu dosen membentuk kelompok mahasiswa secara otomatis dengan mempertimbangkan berbagai faktor seperti:

	      \begin{itemize}
		      \item \textbf{Kecocokan Keterampilan}: Setiap mahasiswa memiliki keahlian berbeda dan setiap tugas membutuhkan kombinasi keahlian tertentu. Edu2Com memastikan setiap kelompok memiliki kombinasi keahlian yang seimbang.

		      \item \textbf{Kepribadian MBTI}: Sistem mempertimbangkan tipe kepribadian mahasiswa (ekstrovert/introvert, rasional/perasaan) untuk pembentukan kelompok.

		      \item \textbf{Preferensi Mahasiswa}: Mahasiswa dapat menyatakan siapa yang ingin mereka ajak bekerja sama, dan Edu2Com akan memenuhi preferensi ini.

		      \item \textbf{Keseimbangan Gender}: Algoritma memastikan setiap kelompok memiliki campuran gender yang seimbang.
	      \end{itemize}

	      \noindent
	      Tes integrasi langsung memvalidasi berbagai skenario dunia nyata:
	      \begin{itemize}
		      \item \textbf{Membentuk Kelompok Seimbang}: Edu2Com membentuk 2 kelompok dengan kombinasi keterampilan frontend+backend di setiap kelompok dan distribusi kepribadian yang beragam.

		      \item \textbf{Menangani Jumlah Ganjil}: Saat 5 mahasiswa tidak dapat dibagi rata, Edu2Com membentuk kelompok 3+2 dengan keterampilan yang memadai di setiap kelompok.

		      \item \textbf{Mengolah Kelas Besar}: Dengan 6 mahasiswa dan 2 tugas kompleks, Edu2Com membentuk 2 kelompok beranggotakan 3 orang dengan distribusi gender seimbang (3 pria, 3 wanita).

		      \item \textbf{Penanganan Kesalahan}: Saat data tidak valid (3 mahasiswa untuk tim beranggotakan 4), Edu2Com mengembalikan pesan error ``Not enough people''.

		      \item \textbf{Batas Kapasitas}: Saat tugas melebihi jumlah mahasiswa, Edu2Com membentuk jumlah tim yang mungkin (2 tim untuk 4 mahasiswa) daripada gagal total.

		      \item \textbf{Kecepatan Respon}: Semua skenario diselesaikan dalam waktu kurang dari 5 detik (rata-rata 2-3 detik).
	      \end{itemize}
\end{enumerate}

\noindent
Tes integrasi langsung di-\textit{skip} secara default dan hanya dijalankan saat variabel lingkungan \texttt{EDU2COM\_INTEGRATION=1} diatur. Pemisahan ini dilakukan karena tes integrasi langsung memerlukan koneksi internet aktif dan bergantung pada ketersediaan layanan eksternal Edu2Com API, yang dapat menyebabkan \textit{flakiness} dalam \textit{continuous integration pipeline}. Dengan memisahkan tes integrasi ini, pengembang dapat menjalankan tes unit secara cepat tanpa bergantung pada layanan eksternal, sementara tes integrasi dapat dijalankan secara berkala untuk memverifikasi konektivitas dengan Edu2Com API.

\subsubsection{Analisis Hasil Pengujian per Area Fungsional}

Hasil pengujian menunjukkan bahwa sistem EduTeams telah lulus seluruh pengujian. Berikut adalah analisis per area fungsional:

\begin{enumerate}
	\item \textbf{Manajemen Kelas (47 tests)}: Pengujian mencakup seluruh operasi CRUD kelas, pembagian \textit{share token} untuk pendaftaran mahasiswa, manajemen daftar mahasiswa, dan validasi akses berdasarkan \textit{role}. 	\item \textbf{Pembentukan Kelompok (20 tests)}: Pengujian fokus pada integrasi dengan Edu2Com API untuk algoritma pembentukan kelompok, validasi parameter pembentukan kelompok (jumlah kelompok vs ukuran kelompok), penanganan \textit{error} API eksternal, dan fitur \textit{reset teams}. \end{enumerate}

\subsubsection{NF-04: \textit{Supportability} (Dukungan Multi-Bahasa)}

Dukungan multi-bahasa diuji melalui 13 tes yang mencakup pengaturan bahasa, konten terjemahan, dan fungsionalitas pengganti bahasa. Seluruh tes berhasil dengan tingkat keberhasilan 100\% pada desktop.

\textbf{Pengaturan Bahasa (2/2 tes lulus):} Sistem mendukung bahasa Indonesia (default) dan Inggris (prefix \texttt{/en}).

\textbf{Pengganti Bahasa (2/2 tes lulus desktop):} Komponen pengganti bahasa ditampilkan pada halaman utama dan berfungsi dengan benar untuk berpindah antar bahasa.

\textbf{Konten Terjemahan (3/3 tes lulus):} Konten ditampilkan dalam bahasa yang dipilih. Sistem memiliki 173 \textit{translation keys} per bahasa dengan cakupan 100\%.

\textbf{Kelengkapan Terjemahan (1/1 tes lulus):} Halaman utama memiliki terjemahan untuk kedua bahasa.

\textbf{Format Tanggal (1/1 tes lulus):} Tanggal diformat sesuai bahasa yang dipilih.

\textbf{Error Messages (1/1 tes lulus):} Halaman 404 menampilkan pesan \textit{error} dalam bahasa yang dipilih.

\textbf{RTL Support (1/1 tes lulus):} Sistem menggunakan LTR (Left-to-Right) untuk Indonesia dan Inggris.

\subsubsection{NF-05: \textit{Security} (Keamanan Sistem)}

Keamanan sistem diuji melalui 14 tes yang mencakup proteksi rute, \textit{security headers}, autentikasi, proteksi CSRF, otorisasi berbasis peran, dan validasi input. Seluruh tes berhasil dengan tingkat keberhasilan 100\%.

\textbf{Proteksi Rute (10/10 tes lulus):} Sistem mengalihkan pengguna tidak terautentikasi dari semua halaman terlindungi: Dashboard, Onboarding, Profile, dan Manage. Halaman publik dapat diakses tanpa autentikasi.

\textbf{Security Headers (5/5 tes lulus):} Sistem mengimplementasikan \textit{security headers} standar:
\begin{itemize}
	\item \texttt{Content-Security-Policy}: Mengontrol sumber daya yang dapat dimuat
	\item \texttt{X-Frame-Options: DENY}: Mencegah \textit{clickjacking}
	\item \texttt{X-Content-Type-Options: nosniff}: Mencegah MIME type sniffing
	\item \texttt{Referrer-Policy}: Mengontrol informasi \textit{referrer}
	\item \texttt{Permissions-Policy}: Membatasi akses fitur \textit{browser}
\end{itemize}

\textbf{Alur Autentikasi (1/1 tes lulus):} Sistem tidak mengekspos \textit{session tokens} di URL, menggunakan Google OAuth 2.0 dengan manajemen sesi berbasis \textit{cookies}.

\textbf{Proteksi CSRF (1/1 tes lulus):} Endpoint API tidak mengizinkan request GET untuk mutasi data.

\textbf{Otorisasi Berbasis Peran (2/2 tes lulus):} Sistem membedakan rute Dosen dan Mahasiswa, dan melindungi rute manajemen dari akses tidak sah.

\textbf{Validasi Input (1/1 tes lulus):} Parameter tidak valid ditangani dengan aman tanpa eksekusi kode berbahaya.

\textbf{Keamanan Sesi (1/1 tes lulus):} Data sensitif tidak bocor di JavaScript \textit{client-side}.

\textbf{Implementasi Keamanan:}
\begin{itemize}
	\item \textit{Authentication}: Google OAuth 2.0
	\item \textit{Authorization}: Role-based access control (RBAC)
	\item \textit{Input Validation}: Zod schemas (96-100\% cakupan)
	\item \textit{SQL Injection Prevention}: Prisma ORM
	\item \textit{XSS Prevention}: React \textit{auto-escaping}
	\item \textit{CSRF Protection}: Next.js bawaan
	\item \textit{Session Management}: \textit{Encrypted cookies}
\end{itemize}
